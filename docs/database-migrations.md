# Database Migrations

GanaTrack uses [Drizzle ORM](https://orm.drizzle.team/) with `drizzle-kit` as the single source of truth for database schema management.

## Configuration

- **Config file**: `packages/database/drizzle.config.ts`
- **Schema definitions**: `packages/database/src/schema/index.ts`
- **Migrations output**: `packages/database/migrations/`
- **Development database**: SQLite (`packages/database/dev.db`)
- **Production database**: PostgreSQL

## Workflow

### Local Development (SQLite)

For rapid iteration during local development, use `db:push` to sync your schema directly to the SQLite database:

```bash
pnpm --filter @ganatrack/database db:push
```

This applies schema changes directly without generating migration files. Use this only for local development — **do not use `db:push` in production or CI**.

### Generating Migrations

When you make changes to the schema definitions in `packages/database/src/schema/`, generate a migration file:

```bash
pnpm --filter @ganatrack/database db:generate
```

This creates a new SQL migration file in `packages/database/migrations/` with the differences between the current schema and the previous migration state.

### Applying Migrations

Apply all pending migrations in order:

```bash
pnpm --filter @ganatrack/database db:migrate
```

This is the **recommended approach for production and CI environments**. Migrations are applied sequentially and tracked in the `__drizzle_migrations` table.

### Database Studio (GUI)

Open Drizzle Studio to browse and query your database visually:

```bash
pnpm --filter @ganatrack/database db:studio
```

## Summary

| Command | Purpose | Environment |
|---------|---------|-------------|
| `db:push` | Sync schema directly to DB | Local dev only |
| `db:generate` | Create migration SQL file | All environments |
| `db:migrate` | Apply pending migrations | All environments (recommended for prod) |
| `db:studio` | Open GUI database browser | Local dev only |

## Important Notes

- **Never manually edit migration SQL files** — they are generated by `drizzle-kit generate`.
- **Always review generated migrations** before committing to ensure they match your intent.
- **`db:push` is for local dev only** — it does not generate migration files and will not work the same way on PostgreSQL.
- **Production deployments must use `db:migrate`** — never `db:push` in production.
- If you have an existing database created by a deprecated script (`push-schema.ts`), delete it and run `db:migrate` or `db:push` to recreate it with the correct schema.
